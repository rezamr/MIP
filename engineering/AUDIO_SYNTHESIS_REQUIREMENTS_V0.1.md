# MIP Audio Synthesis Requirements v0.1

## Purpose

Define what the local MIP application must synthesize, what can be called historically exact, and what must remain labeled as reconstructed or experimental.

## Critical status rule

The application must not label any generated file as an exact 1983 Gateway or CENTER LANE Hemi-Sync reconstruction unless every material parameter is source-verified.

Current enabled baseline conditions may be synthesized exactly as MIP-defined test conditions, but historical identity must remain separate.

## Required synthesis layers

The engine must support a layered stereo signal graph with independently configurable and logged components:

1. one or more left/right carrier pairs;
2. binaural frequency differences;
3. monaural within-channel carrier spacing;
4. amplitude envelopes;
5. optional amplitude modulation;
6. optional frequency modulation;
7. optional masking noise;
8. optional phased/swept masking noise;
9. optional cue tones;
10. future optional voice inserts;
11. fade-in/fade-out;
12. final gain normalization and headroom.

Every layer must be represented in the session audio manifest and included in the audio-file hash.

## Patent-grounded phased-pink reconstruction capability

Robert Monroe patent US 5,356,368 describes a later Hemi-Sync implementation in which:

- noise is generated by a 16-bit shift-register algorithm;
- the sequence repeats after 65,535 samples in the described implementation;
- the noise is filtered toward pink/red rather than white noise;
- the filtered noise is stored in a delay line;
- for each stereo channel the filtered noise is averaged with an earlier delay-line sample, producing a comb-filter response;
- a low-frequency sine/cosine pair sweeps the comb-filter delay;
- the approximate sweep rate is 1/8 Hz;
- the left and right sweeps can have configurable phase/amplitude relationships;
- the resulting noise is multiplied by an envelope;
- the same patent also describes carrier patterns using amplitude and frequency modulation and a Septon multi-carrier architecture.

The app must therefore implement a versioned `PHASED_PINK_PATENT_5356368` synthesis mode that follows the recoverable patent architecture as closely as practical.

Any parameter not recoverable from the patent must be explicitly stored as an MIP reconstruction parameter and must not be silently guessed.

## Determinism and reproducibility

Every generated noise bed must be reproducible from a stored seed and algorithm version.

Store at minimum:

- generator algorithm ID;
- seed;
- sample rate;
- channel count;
- noise-filter coefficients;
- delay-line length/range;
- sweep frequency;
- left/right sweep phase relationship;
- envelope parameters;
- carrier frequencies;
- modulation parameters;
- component gains;
- final normalization rule;
- duration;
- final SHA-256.

## Initial audio conditions

The first operational comparison remains intentionally simple:

- `A-U396-4` — MIP user baseline;
- `A-P100-104` — exact simple Monroe patent comparator;
- `A-SHAM-0` — matched no-beat control.

For this first block, pure-tone versions remain valid because the purpose is to isolate the carrier/beat variable.

Phased-pink/noise layers must not be added to only one condition in the same comparison block unless the protocol explicitly changes the tested variable.

## Later layered conditions

After the simple baseline is stable, add separately versioned conditions for:

- carrier + ordinary pink masking;
- carrier + patent-derived phased-pink masking;
- Septon without noise;
- Septon + phased-pink masking;
- amplitude/frequency-modulated carrier patterns;
- future CENTER LANE reconstructions when source semantics are verified.

## Verification tests

Automated tests must verify:

- exact carrier frequencies;
- exact left/right channel assignment;
- requested binaural differences;
- Septon component frequencies;
- deterministic noise reproduction from the same seed;
- expected noise spectral slope within tolerance;
- delay-sweep frequency within tolerance;
- stereo phase relationship for phased-pink mode;
- no clipping;
- normalization consistency;
- WAV metadata and sample rate;
- SHA-256 reproducibility.

## Interpretation rule

A patent-grounded audio implementation is a faithful engineering reconstruction of the documented patent architecture, not proof that the same complete waveform was used in earlier Gateway/CENTER LANE sessions or that the waveform produces anomalous communication.
